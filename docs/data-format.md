# Data format

Reference for the files in `data/`: for data contributors, and for anyone
checking the data. Field names match `src/dataset/schema.ts`, which is the
authority if this page and the code ever disagree. Terms follow
[CONTEXT.md](../CONTEXT.md).

To change the data, see [contributing-data.md](contributing-data.md).

## Files

| File | What it is |
|---|---|
| `data/jurisdictions/eu.json` | The directive itself, Directive (EU) 2019/882. Also holds the harmonisation status. |
| `data/jurisdictions/se.json`, `de.json`, `es.json` | One jurisdiction file per member state: Sweden, Germany, Spain. |
| `data/en-301-549-v3.2.1-clause9.json` | The clause 9 criteria table. Generated by a script; do not edit by hand. |

A jurisdiction file is named after its jurisdiction code in lower case. Only
files listed in `PUBLISHED` in `src/dataset/index.ts` are loaded.

## Jurisdiction file

### Top-level fields

| Field | Required | Content |
|---|---|---|
| `jurisdiction` | yes | The jurisdiction code, for example `"SE"`. Must match the file name. |
| `name` | yes | The jurisdiction's name in English, for example `"Sweden"`. |
| `instrument` | yes | The instrument the claims are about, for example `"Lag (2023:254) om vissa produkters och tjänsters tillgänglighet"`. |
| `sources` | yes | At least one source. See [Sources](#sources). |
| `claims` | yes | The claims. See [Claims](#claims). |
| `harmonisation` | EU file only | The harmonisation status. See [Harmonisation status](#harmonisation-status). |
| `unverified` | yes | A list of strings; may be empty. See [Unverified](#unverified). |

A trimmed example, from `se.json`:

```json
{
  "jurisdiction": "SE",
  "name": "Sweden",
  "instrument": "Lag (2023:254) om vissa produkters och tjänsters tillgänglighet",
  "sources": [
    {
      "id": "sfs-2023-254",
      "title": "Lag (2023:254) om vissa produkters och tjänsters tillgänglighet",
      "identifier": "SFS 2023:254",
      "kind": "consolidated-text",
      "url": "https://www.riksdagen.se/sv/dokument-och-lagar/dokument/svensk-forfattningssamling/lag-2023254-om-vissa-produkters-och-tjansters_sfs-2023-254/",
      "language": "sv",
      "retrievedAt": "2026-11-08",
      "verify": "quote",
      "note": "Consolidated to SFS 2026:1026, …"
    },
    …
  ],
  "claims": {
    "penalties": {
      "value": {
        "summary": "Orders to comply (32–34 §§), which may carry a conditional fine (35 §, no amount stated), and an administrative penalty fee (37–40 §§).",
        "currency": "SEK",
        "maxFine": 10000000,
        "tiers": [{ "label": "sanktionsavgift", "min": 10000, "max": 10000000 }]
      },
      "citations": [
        {
          "source": "sfs-2023-254",
          "pinpoint": "Lag (2023:254) 39 § första stycket",
          "quote": "Sanktionsavgiften ska bestämmas till lägst 10 000 kronor och högst 10 000 000 kronor.",
          "translation": "The administrative penalty fee shall be set at no less than SEK 10,000 and no more than SEK 10,000,000."
        }
      ]
    },
    …
  },
  "unverified": [
    "No vite amount is stated in the act (35 § only permits förelägganden to be combined with vite).",
    …
  ]
}
```

Every object in the file is strict: a field the schema does not know is a load
error, not something to ignore. A misspelt optional field or claim id
(`notes`, `supervisoryAuthorty`) stops the file loading, with a message such as
`claims: Unrecognized key: "supervisoryAuthorty"`.

### Allowed jurisdiction codes

`EU` for the directive, plus the 27 member states:

`AT BE BG CY CZ DE DK EE ES FI FR GR HR HU IE IT LT LU LV MT NL PL PT RO SE SI SK`

Greece is `GR`, not `EL`. Nothing outside the EU is allowed: the EAA is an EU
directive, so a UK or Norwegian law filed under it would be a category error,
however similar it looks. The tests check that `GB` and `NO` are never published.

Today four are published: `EU`, `SE`, `DE`, `ES`.

## Sources

A source is one official document that citations quote.

### Fields

| Field | Required | Content |
|---|---|---|
| `id` | yes | Lower-case letters, digits and hyphens, starting with a letter or digit, for example `bfsg-37`. Unique within the file. Citations refer to it. |
| `title` | yes | The document's title. |
| `identifier` | no | Its official identifier: CELEX number, SFS number, BGBl reference, BOE id. |
| `kind` | yes | One of six values; see below. |
| `url` | yes | Where the text can be read. Must be an official domain (see [Editorial rules](#editorial-rules)). |
| `language` | yes | The language of the text at that URL: `en`, `sv`, `de` or `es`. |
| `retrievedAt` | yes | The date someone last confirmed the quotes at that URL, as `YYYY-MM-DD`. |
| `verify` | yes | `quote` or `manual`; see below. |
| `note` | no | Anything a reader needs to know about the source: what it was consolidated to, why it cannot be fetched, or a legal caveat. |

A new language needs a code change; see
[contributing-data.md](contributing-data.md#register-it-in-code).

### Source kinds

| `kind` | Use it for | Example in the data |
|---|---|---|
| `legislation` | The text of a law as adopted, on an official legislation site. | `dir-2019-882`, the directive on EUR-Lex |
| `consolidated-text` | A law with later amendments worked in, from the official consolidation service. | `bfsg-37` on gesetze-im-internet.de; `ley-11-2023` on boe.es |
| `official-gazette` | The law as printed in the official gazette. | `bgbl-2021-i-2970`, the German federal gazette |
| `authority-page` | A page published by a supervisory authority about itself or its work. | `mlbf-about`, the MLBF describing itself |
| `commission-page` | A European Commission web page. | `commission-harmonised-standards` |
| `search` | Defined in the schema. No shipped file uses it, and the schema does not say what it is for. | none |

An `authority-page` is weaker evidence than a law: it says what the authority
says about itself, not what a law designates. Say so in the source's `note`, as
`mlbf-about` does: "The authority describing itself. Not a designating
provision."

### quote or manual verification

`verify` says how the source is re-checked.

- `quote`: `scripts/verify-sources.ts` fetches the URL and checks that every quote
  citing this source is still in the text. Use this whenever the URL serves the
  text as a normal web page.
- `manual`: a script cannot read the URL, for example because the site serves
  the document through a JavaScript viewer with session-bound links. The German
  federal gazette (`bgbl-2021-i-2970`) is the one case today.

`manual` does not mean "not checked". Every verification run lists the manual
sources at the end, and a person must open each one, confirm each quote at its
pinpoint, and update `retrievedAt`. Say in the source's `note` why a script
cannot fetch it. See [verification.md](verification.md#a-manual-source-is-due).

## Citations

A citation says where a claim's value comes from.

### Fields

| Field | Required | Content |
|---|---|---|
| `source` | yes | The `id` of a source listed in the same file. |
| `pinpoint` | yes | The place in the source the quote comes from. |
| `quote` | yes | Verbatim text from the source, in its language. |
| `translation` | when the source is not in English | An English translation of the quote. |
| `note` | no | Anything a reader needs to know about this citation. |

When a file loads, each citation's `source` id is replaced by the whole source
entry. Callers never see a bare id.

### Writing a pinpoint

Be as precise as the text allows: article, paragraph, sentence, point. Use the
source's own words for its parts. Examples from the data:

| Jurisdiction | Pinpoint |
|---|---|
| EU | `Article 32(1), second subparagraph` |
| SE | `Lag (2023:254) 39 § första stycket` |
| SE | `Lag (2023:254) 2 § (definition 'mikroföretag')` |
| DE | `BFSG § 37 Absatz 2 (offences listed in § 37 Absatz 1)` |
| DE | `Gesetz vom 16. Juli 2021 (BGBl. I S. 2970), Artikel 3 Satz 1` |
| ES | `Ley 11/2023, disposición transitoria única, apartado 2` |
| ES | `Real Decreto Legislativo 1/2013, artículo 96, letra c)` |

Name the instrument in the pinpoint when the file has more than one source, so
the pinpoint reads on its own. Add a short explanation in brackets when the
provision alone would mislead, as the German penalties pinpoint does.

For a web page with no numbered parts, name the page or the section heading:
`MLBF website, page 'Die Marktüberwachungsstelle stellt sich vor' (Über Uns)`.

### Writing a quote

- Copy the text exactly, in the source's language. Do not correct spelling or
  modernise it.
- Keep it short: at most 30 words (see [Editorial rules](#editorial-rules)).
  Quote enough to support the value and no more.
- Mark each omission with `…` or `[…]`. Each piece either side must appear in the
  source, in the order given. Example from `de.json`:

  ```
  Absatzes 1 Nummer 1, 7, 8, 9 und 10 mit einer Geldbuße bis zu hunderttausend Euro und in den übrigen Fällen … bis zu zehntausend Euro
  ```

- Do not add words of your own inside the quote. Explanations go in the
  pinpoint, the claim's `note` or the citation's `note`.

The checker reads the page as plain text. It drops markup, decodes entities,
folds curly quotes to straight ones and en and em dashes to hyphens, and
collapses whitespace. So typographic differences do not matter, but every word
and number must match. Details are in [verification.md](verification.md).

### Translations

Every citation of a source whose `language` is not `en` needs a `translation`. A
file without one does not load.

Translations are written by whoever adds the citation. They are there so a
reader can check the quote without reading the language. They are not official
translations, and a report should cite the original.

Machine translations are allowed if they are marked as machine translations and
reviewed before merge. Mark one in the citation's `note`, for example
`"note": "Machine translation, reviewed by <name>."`. The schema has no
dedicated field for this.

## Claims

A claim is one fact about a jurisdiction's obligations. Every claim has the same
outer shape:

```json
{
  "value": { … },
  "citations": [ { … } ],
  "note": "optional"
}
```

`citations` must have at least one entry. There is no way to write a value
without saying where it came from ([ADR 0001](adr/0001-every-claim-carries-its-citation.md)).

### Claim list

| Claim id | Required | Value fields |
|---|---|---|
| `applicationDate` | yes | `date` |
| `transpositionDeadline` | no | `date` |
| `microenterpriseExemption` | yes | `appliesTo` |
| `microenterpriseDefinition` | yes | `employeesFewerThan`, `maxAnnualTurnoverEur`, `maxAnnualBalanceSheetTotalEur`, `test` |
| `presumptionOfConformity` | yes | `basis`, `namesEn301549Version` |
| `nationalStandardReference` | no | `standard`, `edition`, `appliesTo` |
| `supervisoryAuthority` | no | `summary`, `bodies` |
| `penalties` | yes | `summary`, `currency`, `maxFine`, `tiers` (optional) |
| `transitionalServiceContracts` | yes | `rule`, `until` |
| `transitionalSelfServiceTerminals` | no | `rule`, `maxYearsAfterFirstUse` |

Dates are `YYYY-MM-DD`. Amounts are whole numbers, zero or more, in the unit
the field names.

An optional claim that is missing means the dataset has no value for it. If you
looked and could not confirm it, say so in `unverified` instead of leaving it
silently out.

### applicationDate and transpositionDeadline

```json
"applicationDate": { "value": { "date": "2025-06-28" }, "citations": [ … ] }
```

- `applicationDate.value.date`: the date the obligations apply from. Cite the
  provision that sets it: for the EU, Article 31(2); for a member state, the
  commencement provision of its law. The tests require `2025-06-28` in every
  published file.
- `transpositionDeadline.value.date`: the date member states had to transpose
  the directive by. Only the EU file records it (`2022-06-28`, Article 31(1)).

Where some provisions of a law take effect on other dates, keep the main date in
`value` and list the exceptions in the claim's `note`, as `de.json` does.

### microenterpriseExemption and microenterpriseDefinition

```json
"microenterpriseExemption": { "value": { "appliesTo": "services" }, … }
```

`appliesTo` can only be `"services"`. The EAA exempts microenterprises providing
services; this records that the law says so, with its citation.

```json
"microenterpriseDefinition": {
  "value": {
    "employeesFewerThan": 10,
    "maxAnnualTurnoverEur": 2000000,
    "maxAnnualBalanceSheetTotalEur": 2000000,
    "test": "fewer than 10 employees, and annual turnover or annual balance sheet total of at most EUR 2 million"
  },
  …
}
```

- `employeesFewerThan`: the headcount the enterprise must be below. A positive
  whole number.
- `maxAnnualTurnoverEur`, `maxAnnualBalanceSheetTotalEur`: the thresholds in
  euros.
- `test`: how the thresholds combine, in words. The numbers alone do not say
  whether it is "and" or "or", so write the test out as the law states it.

### presumptionOfConformity and nationalStandardReference

```json
"presumptionOfConformity": {
  "value": {
    "basis": "harmonised standards whose references are published in the Official Journal",
    "namesEn301549Version": null
  },
  …
}
```

- `basis`: always the fixed string shown. It records that the law gives the
  presumption through harmonised standards published in the Official Journal.
- `namesEn301549Version`: the EN 301 549 version the law itself names, for
  example `"EN 301 549 v3.2.1"`, or `null` when it names none. No published
  jurisdiction names one today.

A non-null `namesEn301549Version` in a member state's file makes its
harmonisation status `national_only`, and the conformance sentence then names
that version. Set it only when the law names a version of EN 301 549 in so many
words, and cite that provision. See [Harmonisation status](#harmonisation-status).

```json
"nationalStandardReference": {
  "value": {
    "standard": "UNE 139803",
    "edition": null,
    "appliesTo": "Websites in the scope of título I, including e-commerce sites"
  },
  …
}
```

Use `nationalStandardReference` when a law points to a national standard
separately, as Spain's Ley 11/2023 does for websites. `edition` is `null` when
the law names none. A national standard is not a version of EN 301 549, so this
claim does not change the harmonisation status.

### supervisoryAuthority

```json
"supervisoryAuthority": {
  "value": {
    "summary": "Post- och telestyrelsen supervises e-commerce, banking and electronic communications services, and coordinates the other supervisory authorities.",
    "bodies": [
      {
        "name": "Post- och telestyrelsen (PTS)",
        "role": "Supervisory authority for e-commerce, banking and electronic communications services",
        "website": "https://pts.se"
      }
    ]
  },
  …
}
```

- `summary`: who supervises what, in a sentence or two.
- `bodies`: each body with its `name`, its `role`, and optionally its `website`.

The EU file has no `supervisoryAuthority`: the directive leaves designation to
member states. Where a law leaves designation to regions, as Spain's does, say so
in `summary` and list what could not be found in `unverified`.

### penalties

```json
"penalties": {
  "value": {
    "summary": "Administrative fines under § 37. …",
    "currency": "EUR",
    "maxFine": 100000,
    "tiers": [
      { "label": "§ 37 Abs. 1 Nr. 1, 7, 8, 9, 10", "min": 0, "max": 100000 },
      { "label": "other offences in § 37 Abs. 1", "min": 0, "max": 10000 }
    ]
  },
  …
}
```

- `summary`: the penalty regime in words.
- `currency`: `"EUR"`, `"SEK"`, or `null` when the text states no amounts.
- `maxFine`: the highest fine the law states, in `currency`. `null` when it
  states none. The EU file has `null` for both, because the directive leaves
  amounts to member states.
- `tiers`: optional. Each tier has a `label` and a `min` and `max`. Use the law's
  own names for its tiers where it has them (`"graves (serious)"`). Use `0` for
  `min` when the law states no minimum.

A claim may cite several provisions. Spain's cites six: the act that points to
the penalty regime, and each article of that regime.

### transitionalServiceContracts and transitionalSelfServiceTerminals

```json
"transitionalServiceContracts": {
  "value": {
    "rule": "Services under contracts concluded before entry into force may continue until the contract ends, at the latest 27 June 2030.",
    "until": "2030-06-27"
  },
  …
}
```

- `rule`: the transition in words.
- `until`: the last day the text states, as a date. `null` when the text states
  a period instead of a date, as the directive and Spain do ("five years from
  that date"). Do not work the date out yourself; if you want to record a
  worked-out date, put it in `unverified` with how you got it, as `eu.json`
  does.

```json
"transitionalSelfServiceTerminals": {
  "value": {
    "rule": "Terminals lawfully used before 28 June 2025 may stay in use to the end of their economic life.",
    "maxYearsAfterFirstUse": 10
  },
  …
}
```

- `maxYearsAfterFirstUse`: the longest a terminal may stay in use after it was
  first used, in whole years.

## Harmonisation status

Whether conformity with EN 301 549 gives a presumption of conformity under the
EAA. It has three values:

| Status | Meaning |
|---|---|
| `cited` | The Commission has published a version's reference in the Official Journal under 2019/882. |
| `not_cited` | It has not. EN 301 549 can still be used as a technical benchmark. |
| `national_only` | No Official Journal citation, but the member state's own law names a version. |

It is recorded once, in `eu.json`, as a top-level `harmonisation` block:

```json
"harmonisation": {
  "status": "not_cited",
  "citations": [ … ],
  "note": "optional"
}
```

- `status`: `cited` or `not_cited`. `national_only` describes a member state's
  law and is worked out from its file, so the schema refuses it here.
- `citations`: at least one, in the same shape as a claim's. The block has no
  date of its own: the answer is dated by its oldest citation's `retrievedAt`.

A member state's file must not have a `harmonisation` block. The member state
takes the EU answer, unless its own `presumptionOfConformity` claim names an EN
301 549 version, in which case it is `national_only` and cites its own law.

The trap this guards against: EN 301 549 v3.2.1 is cited under the Web
Accessibility Directive, 2016/2102, for public sector websites. That citation does
not carry over to the EAA. As of 2026-11-08 no standard is cited under 2019/882,
so the status is `not_cited`. If it is ever changed to `cited`, the tests require
a `legislation` source among its citations: the Commission implementing decision
itself. The full reasoning is in
[ADR 0003](adr/0003-harmonisation-status-has-three-values.md).

## Conformance answer

`conformanceFor` in `src/dataset/index.ts` works out what a report may say about
the standard in one jurisdiction. The logic is in `resolveConformance`
(`src/dataset/conformance.ts`):

1. If the jurisdiction is a member state and its
   `presumptionOfConformity.value.namesEn301549Version` is set, the status is
   `national_only`, the basis is `national-law`, the citations are that claim's
   citations, and the version is the one the law names. A caller who asks for a
   different version gets a `VersionMismatchError`.
2. Otherwise the status is the EU file's `harmonisation.status`, the basis is
   `eu`, and the citations are the EU harmonisation citations. The version is the
   caller's, or `EN 301 549 v3.2.1` by default.
3. The WCAG baseline is the caller's, or `WCAG 2.1 AA` by default.
4. The sentence comes from fixed wording in `src/standards/harmonisation.ts`, one
   per status. `mayClaimPresumptionOfConformity` is `true` only for `cited`.
5. `checkedAt` is the oldest `retrievedAt` among the cited sources. The answer is
   no fresher than its oldest evidence.

How to read the answer is in [results.md](results.md#read-a-conformance-answer).

## Unverified

`unverified` is a list of plain sentences: what the research looked for and
could not confirm from an official source. It is required; an empty list `[]`
says nothing is outstanding.

What goes in it:

- a value the law leaves to someone else and no source was found for, for
  example which body each Spanish region designated;
- a provision that was read but not quoted, so it is not a claim;
- an amendment that was not checked;
- a worked-out value the text does not state, with how it was worked out.

How to word an entry: say what is missing, where you looked, and why it is not
recorded. One entry per gap. From `de.json`:

> The Länder Staatsvertrag (or other Land-law act) that founds the MLBF and
> designates it as market surveillance authority for BFSG services. The fetched
> MLBF pages (…) neither name nor link it. Such a treaty would be published in
> Land gazettes, which are not among the permitted sources, so no title, date,
> gazette reference or text is recorded.

An entry is never a claim, and a claim is never written from an entry. If you
cannot quote it from an official source, it stays here. That way a reader can
tell what the dataset does not know from what it does.

## Load rules

`parseJurisdictionFile` in `src/dataset/load.ts` checks every file when it
loads. A file that breaks any rule does not load, and the package does not
start. The error is a `DatasetIntegrityError` that lists every problem at once,
so a hand edit can be fixed in one pass:

```
jurisdictions/de.json does not load:
  - claims.penalties.citations[0]: names source "bfsg-99", which is not listed
  - sources: "bfsg-37" is never cited
  - claims.microenterpriseExemption.citations[0]: quote is in de and has no translation
```

The schema is checked first. If the file does not match it, only the schema
problems are listed, each with its path, and the other rules do not run until
those are fixed:

```
jurisdictions/se.json does not load:
  - sources.0.language: Invalid option: expected one of "en"|"sv"|"de"|"es"
  - sources.0.retrievedAt: Invalid ISO date
  - claims.penalties.citations: Too small: expected array to have >=1 items
```

Then the structural rules, with the exact problem each reports:

| Rule | Problem message |
|---|---|
| The file declares the jurisdiction it is named for. | `jurisdiction: declares DK, but the file is for SE` |
| The EU file has a harmonisation block. | `harmonisation: the EU file must record the harmonisation status` |
| No member state file has one. | `harmonisation: only the EU file records it; member states take the EU answer (ADR 0003)` |
| Source ids are unique. | `sources: id "ley-11-2023" is listed twice` |
| Every citation names a listed source. | `claims.penalties.citations[0]: names source "bfsg-99", which is not listed` |
| Every source is cited at least once. | `sources: "orphan" is never cited` |
| Every quote from a non-English source has a translation. | `claims.applicationDate.citations[0]: quote is in sv and has no translation` |

Citations in the EU harmonisation block are checked too; their paths start with
`harmonisation.citations[…]`.

These rules do not depend on the date or on judgement, so they can run every
time the package loads. Rules that do depend on them are tests, below. A load
check on source age would stop the package working a year after release.

## Editorial rules

`test/dataset.test.ts` checks the shipped data against rules that depend on the
date or on judgement. They run with `npm test` and in CI, never at load.

| Rule | Detail |
|---|---|
| Quotes are short. | At most 30 words per quote, counting the pieces either side of any `…`. Enough to check, not a reproduction of the text. |
| Sources are recent. | Every `retrievedAt` is within the last 365 days and not in the future. A stale source fails with `<code> <id> is stale: run npm run verify-sources and update retrievedAt`. |
| Sources are official. | Every source `url` starts with `https://` and one of: `eur-lex.europa.eu`, `single-market-economy.ec.europa.eu`, `www.riksdagen.se`, `www.gesetze-im-internet.de`, `www.bgbl.de`, `www.boe.es`, `www.mlbf-barrierefrei.de`. |
| Nothing outside the EU. | `GB` and `NO` are never in `PUBLISHED`. |
| The application date. | `applicationDate.value.date` is `2025-06-28` in every published file. |
| The status needs Official Journal evidence. | If the EU status is `cited`, one of its citations is a `legislation` source. |
| A WAD citation alone never makes it `cited`. | If the EU harmonisation quotes mention 2016/2102, the status is not `cited`. |

A new jurisdiction usually needs its official domains added to the list; see
[contributing-data.md](contributing-data.md#register-it-in-code).

## Clause 9 criteria table

`data/en-301-549-v3.2.1-clause9.json` lists the 50 WCAG 2.1 A and AA success
criteria as EN 301 549 v3.2.1 clause 9 numbers them. The scan tools and
`explain_criterion` read it.

```json
{
  "enVersion": "EN 301 549 v3.2.1",
  "wcagVersion": "WCAG 2.1 AA",
  "sources": {
    "en": {
      "url": "https://www.etsi.org/deliver/etsi_en/301500_301599/301549/03.02.01_60/en_301549v030201p.pdf",
      "bytes": 2285361,
      "sha256": "1eee3a1841a94567da8e59f3b19a782ce9ab081c386b6a2a763b8cde13ff5b49",
      "pages": 186
    },
    "wcag": {
      "url": "https://www.w3.org/TR/WCAG21/",
      "bytes": 476496,
      "sha256": "233ac31974ce8575c08932ee1bd71c93879cf9b8426b2bc9b961b3ea8afb8ab6"
    }
  },
  "extractedAt": "2026-11-08T14:34:18.517Z",
  "criteria": [
    {
      "enClause": "9.1.1.1",
      "wcagRef": "1.1.1",
      "level": "A",
      "name": "Non-text Content",
      "wcagUrl": "https://www.w3.org/TR/WCAG21/#non-text-content",
      "enPage": 45
    },
    …
  ]
}
```

| Field | Content |
|---|---|
| `enVersion`, `wcagVersion` | The versions the table is for. |
| `sources.en` | The ETSI PDF it was built from: URL, size in bytes, SHA-256, page count. |
| `sources.wcag` | The WCAG 2.1 Recommendation it was built from: URL, size, SHA-256. |
| `extractedAt` | When the table was built, as an ISO date-time. |
| `criteria[].enClause` | The EN clause number, for example `9.1.4.3`. |
| `criteria[].wcagRef` | The WCAG success criterion number, for example `1.4.3`. |
| `criteria[].level` | `A` or `AA`. |
| `criteria[].name` | The criterion's name, from W3C. |
| `criteria[].wcagUrl` | The criterion's section in the WCAG Recommendation. |
| `criteria[].enPage` | The page of the EN PDF the clause heading is on. |

Where it comes from: `scripts/build-criteria.ts` downloads both documents,
records their size and hash, and parses them. From the EN it reads clauses 9.1
to 9.4 and checks that each requirement names the WCAG criterion its number
implies. From the WCAG Recommendation it takes each criterion's name, level and
anchor. It throws on any disagreement, or if a clause names a criterion that is
level AAA or not in WCAG 2.1.

The table holds no ETSI text. The requirement sentences are read to prove each
pairing and then dropped. ETSI publishes the standard for free download, which
is not permission to republish it. The names come from W3C, whose document
licence allows reuse with attribution. See
[ADR 0005](adr/0005-publish-clause-numbers-not-etsi-text.md).

To rebuild it:

```bash
npm run build:criteria
```

It needs the network. On success it prints a line such as
`50 criteria (A 30, AA 20) from 186 PDF pages` and the EN hash, and overwrites
the file. Compare the new `sources.en.sha256` with the old one: if it changed,
ETSI changed the PDF, and the diff of `criteria` needs reading before it is
committed. The file is checked against its own schema when the package loads,
so a hand edit that breaks its shape fails at once.
